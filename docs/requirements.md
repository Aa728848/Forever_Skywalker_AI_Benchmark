# 需求与范围

状态：已确认。确认日期：2026-09-14。项目版本：0.1.0。

## 目标

构建以真实工程任务为基础的 AI 编码评测系统，覆盖前端、LSP、后端、缓存、边界、多线程、异步并发、耦合与解耦、递归、生命周期、参数解析和性能优化。补充持久化、事务一致性、故障恢复、Unicode、跨平台、认证隔离与可访问性。

用户已确认：

1. AI 在独立任务仓库中开发，通过完成事件或补丁触发验证。
2. 从七个项目提炼真实场景，主要制作可独立复现的任务，保留少量原仓库集成题。
3. 可用验证占 50%，代码质量占 50%；代码质量结合静态检查、性能测量、独立 AI 评审，保留人工复核。
4. Windows 用于开发，正式评测采用固定 Linux 容器，Windows/LSP 专项单列。
5. CLI 负责提交和自动评分；简洁中文 Web 面板用于查看题目、运行记录与报告。
6. 本次交付完整设计文档、55 道题目录、项目初始化、评分核心与关键测试、CLI、API 和基础中文面板。正式夹具、隔离执行器、模型裁判接入留在后续阶段。

## 必要性与边界

| 要求 | 必要性 | 验收方式 |
| --- | --- | --- |
| 真实任务及固定来源版本 | 衡量已有项目中的定位、修改与回归能力 | 每题关联来源、起始版本、契约及缺陷 |
| 四级难度 | 区分局部实现与跨模块故障处理能力 | 12 个核心能力域各覆盖四级 |
| 实际运行验证 | AI 的完成声明不能证明行为正确 | 独立执行器产出的检查与资源证据 |
| 代码质量四维评分 | 可运行的补丁仍可能难维护、过度耦合或低效 | 固定量表、客观证据、带源码定位的评审 |
| 冻结候选与隐藏验证 | 防止测量漂移、评分器被改写和答案泄漏 | 快照哈希、隔离身份、题目与规则版本 |
| 重放与故障记录 | 并发和生命周期问题需要稳定复现 | 种子、线程屏障、故障点、事件序号 |
| 分离基础设施错误 | 机器故障不能冒充模型失败或成功 | 独立状态、同快照重试与错误计数 |
| 简洁查看面板 | 人工审查需要查看分数与对应证据 | 可筛选目录、报告分项与证据列表 |

首版不需要分布式微服务、独立 Redis 集群、全自动模型作答编排、支付、多租户和公开排行榜。缓存是被测能力；评测平台自身只在明确需要时引入缓存。

## 题库与难度

核心题 48 道：12 个能力域 × 4 个等级。原仓库集成题 7 道：每个来源项目一题，单独报告，避免将原仓库环境成本混入核心分数。

| 等级 | 复杂度定义 | 主要证据 |
| --- | --- | --- |
| 简单 | 局部边界，明确契约，有限状态 | 正常及错误输入、关键回归 |
| 中等 | 多状态或异步交错，至少一个模块边界 | 状态转换、取消、差分与契约测试 |
| 困难 | 多模块、真实线程或复杂图结构 | 可控交错、故障注入、资源约束 |
| 极度困难 | 多个故障相互作用、恢复及性能不变量 | 跨层一致性、历史重放、规模曲线与泄漏测量 |

时间长、文件多、断言多都不能单独证明难度高。难度标签目前为设计标签，必须经人工作答和模型试跑校准后发布。相似题族共享代码时要按题族划分公开/保留数据，防止把同一答案改名后重复计分。

## 正式评测用户流程

选择题目与固定运行档案 → 导出独立工作区 → AI 开发 → CLI/宿主适配器报告完成 → 冻结快照 → 验证与代码评审 → 查看证据和分级报告 → 必要时人工复核。

完成信号表达“可以开始验收”，不表达“验收通过”。普通文本、静默时间、窗口状态和进程退出只能作为观测信息。未接入完成协议的 AI 工具可由操作者执行提交命令。允许修复后的再次提交，但每次保留独立 attempt，不覆盖首次结果。

## 初始化与正式能力的区别

当前 `score` 与 `/api/previews` 接受调用者提供的结构化证据，验证协议后进行分数计算。它们始终输出 `mode: preview`，不会执行候选代码，也不会判断证据是否真实。示例输入清楚标注为假设数据。

正式提交命令、AI 完成适配器、候选快照验证、隐藏用例、容器运行、性能采样、LLM 裁判和不可篡改运行事件均尚未实现。详见 [开发阶段](roadmap.md)。
