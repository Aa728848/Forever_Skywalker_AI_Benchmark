# Agent Note: 修复评分门槛与独立裁判证据链，补齐三语言语法分析

Status: implemented

## Problem

前序代码在正式评分中先舍入分组和质量维度，再判断合格门槛，实际不足 70 的结果可能显示合格。取消或基础设施失败时未执行的关键项被错误地标为失败；缺失质量证据仍显示评分已完成。质量输入没有检查非有限数，正式成绩没有区分宿主运行、脚本演练与经过发布校准的隔离运行。

静态规则使用正则，漏掉箭头函数、方法、side-effect import 和 require，字符串中的关键字反而可能扣分；空工作区得到三个满分。Python 与 F# 题没有客观代码证据。独立裁判只有注入接口，没有真实 HTTP 传输；异步调用结束后才计次数，并发可以突破预算，错误调用不消耗额度，判决可引用不存在的材料。

## Decision

- `@fsa/core` 保留未舍入分数作门槛判断，展示时才舍入；检查质量分范围、任务版本、重复检查及质量证据引用。未完成项保留待定，缺质量证据的评分 readiness 为 pending。
- 结果模式区分 local / rehearsal / formal。隔离运行还必须有题目发布、静态校准、性能校准与独立评审四项明确发布条件；显式演练优先，不能把脚本分数升级为正式成绩。
- 新增纯函数 `scoreBenchmark`，按冻结策略对至少 2 次预热和 7 对同环境原始测量计算候选/参考比值中位数、MAD 与公开线性权重分；正确性、样本、环境或阈值不合法时不产生分数。保留全部原始样本，不挑最好一轮。
- 静态规则升级为 0.2.0：TypeScript 使用已依赖的编译器 AST，Python 用隔离的标准库 `ast` 解析，F# 使用本机 SDK 的 `FSharp.Compiler.Service.ParseFile`。三者均不执行候选源码。规则范围、阈值和语言随报告保存；缺源文件、语法错误、外部解析器缺失直接拒绝，不补满分。语言和题目阈值仍须分别校准。
- 真实裁判新增基于原生 fetch 的 OpenAI-compatible Chat Completions 传输，限定超时、输出额度、JSON 完整响应与实际 usage，无自动重试或模型回退。只从 `BENCH_JUDGE_*` 获取端点、模型与令牌，不读取其他项目凭据。
- 裁判适配器串行分配预算，失败且没有实际用量时封闭余量；同轮同材料缓存，独立轮次用 `roundId` 区分。校验请求/判决的题目、模型、规则、提示版本和材料 ID；平台覆盖模型自报成本与时间。`ReviewOutcome.source` 区分模型与脚本。
- `compareReviews` 保留两轮原始判决对应的均值及差异；超过 20 分或可能改变合格门槛时要求人工复核。复核修订持久化由评价编排层负责，本包不覆盖原判决。

## Alternatives considered

未用额外正则修补多语言代码结构，因为相同漏报会持续出现。选择项目现有 TypeScript 编译器、Python 标准库与已安装的 F# SDK，没有新增第三方解析服务。未用模拟性能、固定质量分或未配置模型补齐成绩。未把传输失败自动转成新调用，以免无法知道实际成本时继续超预算。

## Consequences

调用方需在 `QualityEvidence.release` 提供明确的发布证据，并用真实测量与实际判决组装质量输入。三语言分析需要对应运行时；目前 .NET 10.0.301 和 Python 3.13 在开发机已用真实解析过程验证。静态分依然是待校准的预声明规则结果，不能代替独立评审。真实模型凭据仍由用户配置，本次没有调用真实模型。

HTTP 字段与 usage 语义核对来源：[OpenAI token 与 usage 说明](https://help.openai.com/en/articles/4936856-what-are-tokens-and-how-to-count)。这里实现的是显式配置的兼容端点，不自动读取账户或订阅令牌。
