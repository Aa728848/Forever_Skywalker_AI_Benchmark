# Agent Note: CONC-01 重做（取消与超时传播）

Status: implemented

## Problem

CONC-01 在第一轮批量制作时被撤销，当时的判断是“缺陷设计会让检查阶段超时”。
复盘后发现真实原因有三条，与缺陷设计本身关系不大：
1. 起始版本曾经把 `resolve` 丢掉，成功路径永不结算（那确实会挂住检查）；
2. 生成器在自动收敛时写出了**空的** `defectDetectors`，manifest 校验直接失败，看起来像“没有阶段输出”；
3. 重写测试时我用了 vitest 风格，而检查协议要求 TAP（`node --test --test-reporter=tap`），
   于是每个阶段都以“文件级失败、全部检查缺失”收场。

## Decision

- 缺陷设计改成**全部不阻塞**：cancel 与 timeout 都只结算 Promise（不 abort signal），
  成功/失败结算后都不取消定时器。任何一条检查都能在有界时间内拿到结论，不会挂住阶段。
- 检查改用 `node:test` + `node:assert/strict`，与其它题目包一致；时间行为全部走注入的假调度器。
- 撤回的 `defectDetectors` 按实测重新声明（10 项：5 个公开 + 5 个隐藏），并复核每一项都对应真实缺陷。

## Alternatives considered

- 保留“cancel 不结算 Promise”这种更狠的缺陷：会让检查必须等待一个永不到来的结算，
  在 60 秒阶段预算下表现为超时而不是失败，无法区分“被测失败”与“阶段故障”，因此不用。
- 用 vitest 直接跑题目包：检查协议与试点全部基于 TAP 解析，换 runner 会破坏三向验证的可比性。

## Consequences

- 简单档 11/12（只差 THR-01），核心题 17/48。
- 生成器需要一条防呆：自动收敛不允许写出空 `defectDetectors`（否则 manifest 非法，
  报错信息会误导成“阶段无输出”）；这条已记录为待办。
- CONC-01 与 CONC-04 形成同一能力域的简单/极度困难对照：前者考取消与超时传播，后者考并发正确性。
