# Agent Note: 启动前安全补齐项目环境

Status: implemented

## Problem

没有 `.env` 或只配置了部分字段时，用户必须手工复制模板并填写路径、镜像和令牌，容易把评测环境、DSH配置与裁判配置混在一起。启动向导需要在不读取其他项目凭据、不把密钥放进命令参数的前提下完成本项目最低配置。

## Decision

新增 `readProjectEnvironment` / `saveProjectEnvironment`：用 Node 的 dotenv 解析，保留注释、未知键、换行和非空值；只补空值或缺失键。操作系统非空同名变量优先，空值允许文件值补齐。保存前后检查文件文本与文件状态，使用独占锁、同目录临时文件、flush 和原子替换；冲突或无法无损表达时整批拒绝并清理临时文件。返回新的 `effectiveEnv` 给当前启动流程和子进程，不修改全局 `process.env`。

`configureProjectEnvironment` 只在缺少配置或用户从菜单主动选择时询问。基础运行、固定 Linux 镜像、DSH 路径和报告目录按需补齐；已存在的固定镜像从 `data/container/runtime.json` 读取并在实际执行时再次校验。API 令牌随机生成且只在最终保存摘要显示“已填写”。DSH 密钥仍由 DSH 自己管理。

独立裁判表单 `collectJudgeSetup` 只问缺失字段，令牌经过 `secret` 输入，不打印或返回原始提示中的密钥；支持8家供应商和 OpenAI-compatible，思考/协议/预算由既有裁判配置校验器复核。网络可用性不在保存阶段验证，用户可跳过，完整质量分缺失时保持待定。

## Alternatives considered

没有直接覆盖整个 `.env` 或把 `.env.example` 当成用户配置；这样会破坏已有自定义字段与注释。没有把令牌放进 argv、显示在计划命令或写入报告。没有读取 DSH credentials 或探测裁判端点。没有用通用 dotenv 写回库，以避免引入依赖和改变未参与配置的格式。

## Consequences

用户可从 `pnpm start` 完成最小配置后继续选择模型和模式；已有环境保持稳定。并发编辑 `.env` 会被拒绝而不是覆盖。Node dotenv 无法无损表达的特殊值要求使用系统环境变量。保存只对本项目 `.env` 生效，DSH 的供应商密钥和 profile 不会被复制。

## Verification

- `pnpm check`：21个测试文件、247项测试、严格类型、目录检查和生产构建通过。
- 环境保存测试覆盖新建文件、非空 OS 优先、空白值补齐、注释/未知键/多行/CRLF、特殊字符往返、非法值整批拒绝、并发修改与锁、部分写入/替换失败清理。
- 配置向导测试覆盖空环境生成本地令牌和复用固定镜像、取消/放弃不落盘、已有值保留、裁判缺失提示；使用系统临时目录和虚构令牌。
- 裁判表单15项测试覆盖8家供应商、思考参数、预算、已有配置不覆盖、错误字段重填、跳过/取消；未发起网络或模型请求。
- 终端2项测试覆盖退格、方向键历史、Ctrl+C/EOF 取消时密钥不回显。

真实用户 `.env` 未读取或修改；来源仓库、评分题包、固定镜像和裁判凭据均未改变。
