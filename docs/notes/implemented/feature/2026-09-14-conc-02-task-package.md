# Agent Note: CONC-02 重做（任务组的取消传播）

Status: implemented

## Problem

上一轮这道题没有通过验证，两个原因：
1. 我把三处无关缺陷（`active` 不清理、并发上限失效、取消不传播）塞进同一道题，
   结果起始版本一次失败 4 项检查，既不符合“缺陷族聚焦”，也让检出项声明失去意义；
2. 参考实现写得过于复杂（并发闸门 + 等待队列），文件根本没能加载，参考/替代阶段连 TAP 都没有。
另外我当时还把“替代实现”直接复制成参考实现——那会让替代实现这一环形同虚设。

## Decision

- **只保留一个缺陷族**：`cancelAll()` 不 abort signal、不清理 `active`、用普通 `Error` 拒绝且不等待结算。
  其余行为（`active` 生命周期、成员失败隔离）在起始版本里就是对的，因此每个阶段只失败一项检查。
- 参考实现从简：成员存 `Map`，`run` 里记录 `done`（永不拒绝的收尾 promise），
  `cancelAll` 的顺序固定为「先 abort 全部 → 再统一拒绝并清空 → 最后 `await` 全部 `done`」。
- 去掉并发上限这一维（它是上一轮复杂度的来源，也不是这道题的考点）。
- **替代实现必须结构不同**：成员放数组、用 `Promise.allSettled` 等待、用辅助函数增删。

## Alternatives considered

- 保留并发闸门：需要等待队列与槽位回收，参考实现复杂度陡增；移到后续的困难档题目再考。
- 让缺陷表现为“cancelAll 永不兑现”：会让检查挂住（这正是前一轮 FE-02 的教训）。

## Consequences

- 中等档 5/12；核心题 20/48。
- 制作口径明确为两条硬约束：**一个题目包只考一个缺陷族**；**替代实现必须与参考结构不同**。
  这两条已经被验证器实际抓住过，因此不是纸面规矩。
