# Agent Note: ARCH-03 题目包（替换适配器并保持公共契约）

Status: implemented

## Problem

替换底层适配器时最危险的缺陷是语义漂移：字段名一样、含义不同。新适配器用秒、用 `status`、允许空 body，
旧适配器用毫秒、用 `ok`、用可选 payload。直接透传字段，调用方会拿到看起来正常、误差却是 1000 倍的结果。

## Decision

- 冻结 `Repository.read` 的公共契约与 `AdapterError`，两个适配器接口（同步旧版、异步新版）都在工作区里。
- 缺陷族只有一条：**新适配器路径不做契约映射**（缺失当成功、秒当毫秒、异常不包装）。
  旧适配器路径在起始版本里就是对的，因此每阶段只失败与新路径相关的三项检查。
- 参考实现把 v2 结果显式映射到公共形状并统一 try/catch；替代实现先把各自结果归一成 `ReadResult` 再包错误（结构不同）。

## Alternatives considered

- 要求新适配器直接返回旧形状（把迁移成本推给上游）：无法验证调用方是否真的兼容，因此不采用。
- 只测旧路径：那正是换适配器才发现单位错的经典翻车场景，必须两条路径都覆盖。

## Consequences

- 困难档 7/12；核心题 31/48。
- 与 ARCH-02 形成一组：前者考归属由元数据决定，后者考契约由边界决定，都要求把隐式约定写成显式代码。
