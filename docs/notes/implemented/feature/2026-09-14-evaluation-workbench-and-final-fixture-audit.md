# Agent Note: 自动质量评估、运行工作台与全题库审查

Status: implemented

## Problem

用户要求先检查前序问题，再继续完成题库与平台，并配置 Linux 容器。前序交接存在相互矛盾的完成状态；提交后质量评审未自动接入，Web 无实际执行详情，部分题目虽参考通过却缺功能评分组。来源集成仍是设计规格。

## Decision

- 新增 packages/evaluation 作为 I/O 组合层，评分核心继续不读文件/网络。自动组合冻结源码的三语言静态事实、两次预热与七轮性能配对、两轮独立裁判及人工复核。
- PERF-02/04 使用受信专用负载；其它题测量完整验证成本。只使用外部阶段时间评分，内部时间/RSS仅诊断。为 Windows 嵌套采样分配短临时工作目录，证据保留在运行档案。
- 评审保留修改文件的完整前后文，并附直接本地依赖；其它未附全文文件明确列出。超过材料预算只阻止裁判，不丢已取得的静态/性能事实。两轮使用同一材料，不能把第一轮结果混入第二轮输入。
- API 自动评估、取消、同快照重试和人工补评均使用已有权限边界；下载验证 realpath 与哈希。CLI 支持 review/report/summary，评审与测量响应取消。
- Web 增加实际 run/attempt 详情、四维质量、检查/事件/证据与下载；显式选择每题一次作答汇总，拒绝重复、旧题版本和环境混合。汇总记录产生时间、评分修订及评分时间，不隐式挑最高分。
- 修正本机旧成绩标签、异常退出/输出超限仍可能达标的问题；每阶段输出超过8MiB终止并标注截断。质量证据读取冻结源码，补评不覆盖原记录。
- 全题审查发现12题缺少五组之一。补充真实资源/状态/回归验收或按断言实际语义归组；manifest 和 trial 增加门禁，参考必须可用分50/50，缺陷必须在预声明项失败。
- 并行补齐48核心与7固定来源集成，集成保留实际模块、许可/哈希、原基线及外部替身范围。生成器拒绝覆盖既有包，删除反向篡改预声明缺陷检出项的行为。
- 重写当前交接/架构/阶段/记录说明，历史Note保留；最终结果集中于 docs/trials/2026-09-14-full-fixture-audit.md。
- 本项目 .env 已生成独立 API 令牌和本机目录，裁判字段为空。Docker Desktop、WSL与虚拟化组件已安装；构建脚本将基础镜像及最终image ID固定，成功后自动更新本项目执行档案，不覆盖裁判或令牌。

## Alternatives considered

- 沿用调用者自报评分或固定质量分：不能验证AI成果，保留为显式preview/rehearsal演示，不进入真实验收。
- 把所有未改上游源码送审并在超预算时取消整个评估：会令大型集成题丢失客观证据，改为评审与测量分别取得证据，材料缺失明确列出。
- 用宿主结果代替 Linux 容器：不符合已确认环境约束，容器不可用必须拒绝。
- 通过减少检查、重写预期或更改ready标签收尾：破坏评测有效性，保留五组及三向门禁。
- 为单机平台增加独立消息队列和微服务：没有当前需求依据，保留明确包边界及单写者存储。

## Consequences

平台与55道题目包已形成可运行交付，但全部仍为fixture-ready。本机数据不属于正式隔离成绩；静态/性能/难度阈值尚未发布校准。Docker安装要求Windows重启，未自动关闭用户应用；真实裁判尚无用户配置。正式发布还需这些外部条件和实测证据。

隐藏检查在容器运行时可被候选读取，同进程F#/Python验证与内部采样不具备完全防恶意篡改能力。单写者文件记录与哈希也不等于不可篡改存储。集成starter保留原源码结构，在固定契约命令中运行，不冒称已通过来源产品全量类型/测试矩阵。
