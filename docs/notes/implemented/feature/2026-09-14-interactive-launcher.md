# Agent Note: 分阶段终端快速启动

Status: implemented

## Problem

用户希望通过终端逐步选择模型、模式和评测参数，避免手工记忆长命令。原有DSH命令、外部作答流程与网页启动分散；不同供应商同名模型和未声明思考等级的模型也容易选错。

## Decision

新增 `pnpm start`，Windows可双击根目录 `start.cmd`；脚本自动定位项目工作目录并加载本项目.env。使用Node内置readline与现有命令，不增加第三方依赖。

菜单支持DSH自动作答、导出外部题目、提交已完成作答、启动网页/API及Linux环境检查。DSH分五阶段选择供应商/模型、预设/思考等级、题目、预算/报告目录、最终计划。编号或ID选择，逗号多选，回车默认，q/输入结束退出；最终可重新选择参数。模式、等级与重复数的笛卡尔积明确显示为总作答次数，不把Token输出上限当作整题总预算。

模型目录沿用本地DSH已安装适配器，按provider分组，未取得能力时仅预选default，不从另一供应商同名模型继承能力。手工ID和手工等级保留明确入口；目录范围与超时回收见 [本地目录Note](2026-09-14-dsh-local-model-catalog.md)。裁判沿用.env配置，只显示模型/思考/预算状态，不在向导收集或打印令牌。

向导只生成本次运行参数，不重写.env或DSH配置。默认最后执行 `--check`，不自动升级成模型作答；明确选择开始才调用既有评分链路。实际执行传Node argv数组，目录中的空格、引号、&、$()不经过Shell展开；可复制命令单独按PowerShell单引号规则显示。网页分支仅调用固定的pnpm dev，不拼入用户输入。前台子进程使用已有Ctrl+C清理流程，父进程等待退出。

CLI增加parseArgs的allowNegative以支持 `--no-measure`，使外部作答菜单明确选择跳过时覆盖.env中的开启配置；其余参数及评分语义不变。独立审查发现外部作答默认目录若在评测仓库内，编程AI会沿Git父目录看到graders。已将新向导默认目录改到仓库外 `Documents/BenchAnswers`，用户仍可自行选择目标路径。

## Alternatives considered

没有引入终端UI依赖或另做一套评分执行器；直接复用现有CLI，避免参数及清理行为分叉。没有在读取模型列表时启动完整DSH CLI，因为其profile准备步骤会写原配置。没有自动开始真实模型评测或把目录查询当作API凭据认证。默认只预检，实际开始由操作终端的人在计划页明确选择。

## Consequences

日常入口缩短为pnpm start或双击start.cmd。Docker Desktop仍需启动，模型作答与裁判沿用各自现有配置。自定义profile/额外插件可能需要手工填写模型；本地目录不证明远程可用性。选择仅预检后退出向导，实际作答可复制已显示命令或重新打开向导。
