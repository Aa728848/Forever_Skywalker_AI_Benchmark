# Agent Note: 静态客观分（冻结规则的可复现测量）

Status: implemented

## Problem

上一轮把「客观分 + 评审分」的合成规则做完了，但没有任何东西产出客观分：
评分标准要求客观分必须引用 `static`（性能维度必须引用 `benchmark`）证据，
因此真实运行的四个质量维度始终是 null，总分永远出不来。

## Decision

- 新包 `@fsa/static`：`analyzeWorkspace(root, policy)` 对一个候选工作区做**冻结规则的词法级测量**：
  - 剥离块注释、行注释与模板字符串后，按 `function`/`= (...) =>` 的形态切出函数体（花括号配平），
    统计每个函数的决策点（`if`/`while`/`for`/`case`/`catch`/`&&`/`||`/`?`）与行数；
  - 统计 `from '...'`/`import('...')` 的模块说明符；
  - 三条公开规则：简洁度 = `clamp(100 − 10×决策点超阈值函数数)`；
    可维护性 = `clamp(100 − 5×超长函数数)`；解耦性 = `clamp(100 − 25×禁止导入命中数)`；
  - 规则与阈值**由数据传入**（`StaticPolicy`：每函数决策点上限、每函数行数上限、禁止导入、证据 id），
    规则版本为 `staticRuleVersion`，升级规则必须同时提升版本并重新校准阈值。
- 报告包含逐文件事实（路径、行数、函数与决策点、导入）与违规说明，
  可直接作为 `evidence` 引用（`evidenceId`），交给 `scoreExecution` 的 `objective` 输入端。
- 性能维度**不由本包产出**：它必须来自同机 benchmark 证据，缺就保持 null。

## Alternatives considered

- 引入 TypeScript 编译器 API 做真正的 AST 分析：更准，但会把编译器版本与解析行为也变成评分契约的一部分；
  先用公开的词法规则（明确记录限制），把规则版本与阈值留在数据里，后续可按题族替换实现而不改协议。
- 按文件数/行数/测试数量直接判优：评分标准明确禁止跨语言统一按这些量判优，因此改为「阈值超限计数」。
- 让静态分直接决定质量维度：维度仍需评审分参与，缺一半就保持 null。

## Consequences

- 评分链路现在**端到端可算**：受控执行 → 可用验证分；静态规则 → 客观分；评审适配器 → 评审分；
  三者齐备时 `quality` 与 `total` 变成确定值，`thresholdMet` 也按「总分 ≥70、可用验证 ≥40、关键项全过」给出。
- 词法规则的已知限制（不解析 AST、不区分字符串内容、函数名可能为 anonymous）写进了代码注释与本文；
  它衡量的是结构信号，不是语义正确性——语义正确性由可用验证与评审负责。
- 静态规则目前只支持 TypeScript；F# 题（LSP-01、THR-03）在这三条规则下会得到满分（没有 .ts 文件），
  这属于**未校准**状态，必须在接入 F# 规则前如实标注，不能把满分当成质量结论。
- 审计与面板尚未消费静态报告（下一步把它写入运行档案并展示）。

## Verification

- `pnpm check`：exit 0（86 项 vitest）。
- 6 项静态测试：干净实现满分且带规则版本与证据 id；决策点超阈值扣简洁度并留违规说明；
  超长函数扣可维护性、禁止导入扣解耦；非 typescript 规则被拒；空工作区仍产出报告；
  **集成**：静态客观分 + 脚本评审 → 维度 88/86/90/96、`quality=45`、`functional=50`、`total=95`、`thresholdMet=true`。
