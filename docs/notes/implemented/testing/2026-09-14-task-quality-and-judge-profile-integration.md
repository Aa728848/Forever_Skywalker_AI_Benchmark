# Agent Note: 题目质量门禁与裁判配置一致性

Status: implemented

## Problem

用户要求主流裁判思考参数，并质疑现有题目是否过浅。原55题可运行不代表高难度或鉴别力成立；模型名相同但推理参数不同的评审也不能混成同一分数。

## Decision

审查55题并保留原始信号：40题单源码、45题单文件参考补丁、35题直接缺陷提示。这些信号用于复查，不换算成质量分。将API-04与GRAPH-04升级为来源机制可定位、多个不变量相互作用的工程场景，保持核心四级规模与旧接口回归，不以源码体积宣称难度。

新增独立task:mutants入口，先验参考，再对各预声明错误修复运行完整固定检查。必须命中预声明目标，编译崩溃、超时、缺测和未知检查无效。多个真实不变量交叉失败可以保留，避免按观测反向调整全失败集合；这不改变starter三向的精确失败集合规则。

裁判包由独立子任务按8家官方API实现参数与协议，根集成保存冻结配置、两轮配置/实际模型比较、跨作答裁判档案隔离以及离线judge-config命令。差异保持待复核，原功能证据及历史修订保留。参数指纹纳入端点身份但不输出其明文，令牌不进入记录。

UI明确难度标签未校准；需求、评分、架构、交接和题库元数据同步，完整审查记录留在docs/task-quality-review.md。用户暂停实际模型运行的要求保持有效。

## Alternatives considered

- 直接增加大量相似题目：会扩大数量而不能证明区分能力，先做有依据的升级和反例检出。
- 用行数/文件数/断言数给题目打质量分：容易奖惩错误，保留为人工复查信号。
- 只证明一个刻意坏的starter失败：不能排除不完整修复，补充预声明近似修复集。
- 强制所有供应商使用high和temperature=0：不同模型语义不一致，按供应商模型能力校验并记录实际字段。
- 把每个额外交叉断言失败都判为无效反例：会迫使作者追随观测改目标，改为预声明必要检出项、额外真实失败原样展示。

## Consequences

两道工程题的实际契约与错误修复检出证据增强，但其它局部高难题仍需强化/校准；没有作答数据就不能保证极难标签或模型区分率。8供应商通过离线协议测试，真实端点和裁判质量尚待用户启动；本轮不重启、不跑模型、不声称Linux验收。
