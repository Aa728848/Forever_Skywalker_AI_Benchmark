# Agent Note: 前端、生命周期、架构与状态题的工程边界改进

Status: implemented

## Problem

用户要求检查题库能否区分实际工程开发水平。逐题读取 FE、ARCH、LIFE、STATE 共16道题的题面、起始代码和隐藏断言，发现 STATE-01 的参考解会对JSON null抛TypeError，原子性检查只检查成功后无临时文件；ARCH-03/04、STATE-03此前主要是局部字段或循环修复，难以独立支持困难标签。其它几题缺少声明语义下的同步回调、失败发布和重试交错。

## Decision

保留7题的能力范围，改进下表9题，版本均升0.2.0，保留原公开接口和回归。新增契约与五组功能评分资产同步落盘；每题 graders/<ID>/source-evidence.md 记录固定来源提交、实际git show字节SHA-256、已核对锚点与本题新增契约的区别。来源仓库只读。

| 题目 | 新增有效工程边界 | 检查项 |
| --- | --- | ---: |
| STATE-01 | null/数组/标量损坏记录；rename失败保留原值、原错误与回收暂存 | 14 |

FE-01/02/03、STATE-04、LIFE-01/04、ARCH-01保留现有能力范围。基础题承担基础退化检测；已有真实DOM、持久进程退出或进程树回收的题不为增加体量而重做。

## Alternatives considered

- 全部题只扩大输入量或复制公开测试：不能增加有效工程语义，也不能修复参考解/隐藏检查漏洞。
- 将所有基础题改成极难集成题：破坏四级递进体系；本次保留基础门槛。
- 重写原公开接口：使已有作答和回归失去意义。本次用兼容模块或增强原语义维护已有入口。
- 启动真实模型作答校准：用户仍未启动真实模型评测；本次只做题包开发验收，不把参考分冒称模型成绩。

## Consequences

新版困难题要求同时满足多类不变量，修复原注释指出的局部缺陷不足以取得完整功能分。五道困难/极难题各提供3个预声明近似错误修复，分别检验不能被简单成功样例发现的遗漏。中等题增加的是不同故障/隔离边界，没有靠浅层getter检查抬高数量。

全部仍为fixture-ready，难度与模型区分度尚待真实作答校准。本次子任务仅完成Windows本机三向和近似错误修复；Linux全量及平台检查由根任务统一执行后补整体验收。原注释和接口回归保留；不宣称来源中存在本题新API的同名实现。
