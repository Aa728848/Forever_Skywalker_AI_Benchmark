# Agent Note: LSP、边界、并发与线程题的工程区分度升级

Status: implemented

## Problem

本轮审查16道LSP/BND/CONC/THR核心题。7题保留基础能力范围，9题需要增强实际工程约束：单资源FIFO被标成多资源困难题；同步Map假账本被当作进程恢复；已有完整线程回收框架仅缺一次代际比较；Unicode隐藏样例大多重复公开样例；LSP并行检查没有覆盖取消回调重入及文档版本与发布快照的共同约束。

题目区分度不能由文件数、代码行数或超大输入替代。正式难度仍需真实模型作答校准，本轮不调用外部模型。

## Decision

以下9题升为0.2.0。保留既有公开接口和回归，新增交互协议时使用新方法或模块；题面冻结新增行为，未公开检查不自行增加行为要求。

| 题目 | 实际增强 | 检查数 |
| --- | --- | ---: |
| LSP-03 | 取消通知锁外执行、真实线程观察、同URI重开、回调错误后恢复、跨Coordinator身份 | 10 |
| LSP-04 | 文档版本与Build代际门禁、重复结果隔离、真实读线程观察原子View、工作区关闭重开 | 9 |
| BND-02 | 围栏长度、不透明非JSON块、错误优先级、特殊对象键及参数只解码一次 | 17 |
| BND-03 | 全部UTF-8标量边界、任意切分、非法序列全局偏移、错误终结、输入缓冲隔离 | 14 |
| BND-04 | 语法驱动的物化前预算入口、节点/深度错误优先级、严格JSON语法及token偏移 | 11 |
| CONC-02 | TaskGroup与认证刷新/传输共享生命周期，注销取消结果、close等待底层清理、同步重入 | 20 |

| THR-04 | 跨代共享真实线程上限、排队撤销、在途终止确认、close排空与恢复 | 8 |

CONC-04保留旧JobRunner回归，主要题目改名“持久分片归并、崩溃恢复与代际发布”。prepare/publish由单协调者串行执行，completeShard允许多进程并行；不声称任意外部副作用恰好一次，也不与API-04的租约领取协议重复。

LSP-01明确分帧输入范围，BND-01移除与实际starter不符的“重复取第一次”描述，CONC-01明确注入Scheduler回调时序，THR-03明确写优先与不可递归进入的范围。这4项为澄清，未修改实现或检查。

7道困难/极难增强题分别提供3种预声明近似错误修复，共21种；目标依据冻结不变量确定，额外交叉失败原样保留。BND-02、CONC-02为中等题，未为数量增加无意义变体。

## Alternatives considered

- 仅增加样本量或把数据变成数百万条：不能补足生命周期与故障模型，未采用。
- 把CONC-04改成另一个租约任务队列：与API-04重叠，改用不可变计划、分片和单协调者发布。
- 删除旧公开接口以简化新场景：破坏现有作答协议，保留兼容回归并增加实际组合路径。
- 用固定sleep证明线程正确：主要采用共享屏障、线程创建/退出观察和F#读线程启动握手；超时只限制失败检查，不能记作成功检出。

## Consequences

九题共有120项实际检查，旧缺陷与新增交互缺陷均可区分。替代实现包含不同结构：LSP映射/字典、BND-04状态栈/指令栈、CONC-03冲突屏障集合/前序请求比较、THR-04实例调度器/串行代际切换后并行lane、CONC-04数组计划/键映射计划。题目仍为fixture-ready，未校准的极难标签不是已测出的模型难度。

源项目只读；原始代码未直接复制进新题。来源机制和本轮审查锚点见[来源证据](../../../reviews/2026-09-14-lsp-boundary-concurrency-evidence.md)。本机当前来源HEAD与目录原始来源固定提交可能不同，二者在证据中明确区分，未擅自更新七个来源仓库或全局来源清单。
