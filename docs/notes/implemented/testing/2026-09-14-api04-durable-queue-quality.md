# Agent Note: API-04 从内存幂等例题升级为持久队列综合题

Status: implemented

## Problem

用户要求检查题库是否过浅，并从七个参考项目提炼更复杂、有工程意义的任务。API-04 0.1.2 虽标极度困难，实际用 Map 包装 TaskStore，重启只换对象，写失败在存储变更前抛出；这只能证明基础幂等，不能证明跨进程事务或恢复。

## Decision

将同一题升为 0.2.0，题名为“持久任务队列：并发领取、租约隔离与崩溃恢复”。旧 TaskSubmitter 的公开行为保留并作为已修复的回归基线；新增 DurableQueue / QueueStorage / worker / model，使作答需要在多个模块间保持以下条件：

- 请求身份、内容绑定、提交结果与确认丢失后重试一致。
- 真实多进程领取排他，租约到期重领增加代际，同名旧 worker 无权提交结果。
- 结果、完成状态和修订原子生效；执行中的外部副作用允许重放，不能声称任意外部工作恰好一次。
- 幂等重放不增长文件或历史，快照隔离和关闭资源可验证。

来源固定在 harness 2377c272a8e839e0a84c9f0e623b867a1dce2014 的 lease.ts / generation.ts / atomic-write，以及 trading b6cf5535093cdc43fc61a7037d997bace7fb0e6d 的 tasks/ledger.ts。先使用来源仓库 CodeGraph（有索引时），再通过 git show 读取固定提交。路径、Git blob、SHA-256 见 graders/API-04/source-evidence.json。未修改来源仓库，也未复制受不同许可约束的模块。

受信检查使用实际 SQLite 临时文件和真实子进程：三个未提交阶段进程退出、两个已提交阶段确认丢失；标准输入/输出屏障控制两个进程交错，等待 close 保证收齐输出。固定种子预言机穿插重开数据库。参考使用关系表事务，替代使用单行文档原子变换，允许不同内部结构。

新增 3 个近似错误修复补丁并接入根代理的 task:mutants：按键去重却不绑定内容、只校验 worker 名称、SQL 自动提交导致部分状态。缺陷检出项在运行前声明，没有根据实际失败反写预期。

## Alternatives considered

- 仅扩大原内存提交次数：无法增加事务、跨进程和恢复的证据，未采用。
- 完整移植来源服务、认证、调度 UI 和依赖树：把安装工作混入核心协议难度，超出独立任务范围，未采用。
- 只提供一个正确实现并检查源码形状：会绑定具体表结构和解法；采用结构不同替代与语义变异检查。
- 强制外部副作用恰好一次：无法由独立数据库事务保证，公开约定外部工作可重放，结果提交受代际约束。

## Consequences

保留 55 道题的数量，提升其中一题的版本和意义；旧成绩不能与 0.2.0 直接比较。26 项声明检查覆盖五个功能组，其中 14 项为新增持久协议。公开题面给出症状、接口、边界和故障屏障，未直接标注修复代码位置。

仍为 fixture-ready。“极度困难”是结构性设计目标，未经不同模型和人工的难度校准。本次没有运行被测模型、真实裁判、Linux 容器或重启 Windows。进程退出测试不等于硬件断电证明；来源场景缩编也不等于在原仓库复现其所有问题。
