# 题目质量审查与提升

审查日期：2026-09-14。结论：原题库具备可执行的正反对照，但不足以证明所有“困难/极度困难”标签成立，也没有实际模型作答数据证明其区分能力。本轮在保留48核心、7集成规模及50/50量表的前提下，先升级代表性工程任务并增加错误修复反例验证。

## 修订前的证据

全55题源码与参考补丁审查快照位于 `data/quality-audit/before-upgrade.json`。40题仅有一个源码文件，45题参考补丁只改一个文件，35题的起始代码包含“缺陷：”等直接提示。这些是人工复查信号，不是自动质量分；真实工程缺陷也可能只需一行修复。

结合题面与验收语义，存在以下明确问题：

| 题目及修订前版本 | 实际任务 | 质量判断 |
| --- | --- | --- |
| GRAPH-04 0.1.1 | 静态图反向可达性、环与深图终止 | 算法回归有用，但没有批次图更新、派生缓存和异步发布，难以单凭此认证极难工程能力 |
| API-04 0.1.2 | 同步内存store的幂等映射，新实例模拟重启 | 幂等有用，但没有持久并发领取、提交中断和跨进程事务；“重启一致性”覆盖面有限 |
| ARCH-04 0.1.0 | 同步setup/teardown的顺序与异常回滚 | 可作局部资源所有权题；题面直接给定操作顺序，尚不能代表复杂插件热更 |
| STATE-03 0.1.0 | 根据内存检查点选择重放起点 | 是基础重放回归；未覆盖真实日志破损、事务中断及检查点原子提交 |
| PERF-04 0.2.0 | 一次遍历计算会话摘要，配对测量 | 能识别重复扫描，但缺完整流式会话/投影重建；事件数大不自动等于高难度 |
| 来源集成题 | 多模块原源码与明确外部替身 | 比孤立函数更接近工程；部分缺陷仍是少量局部修复，源码体积和“集成”名称不能替代鉴别力证据 |

既有55题三向和受控试跑证明参考实现可用、起始缺陷可检出；它们不是55次AI作答，更不是难度校准。公开与隐藏测试若只是相同断言换名字，也不能增加有效覆盖。

## 本轮新增的工程场景

### API-04：持久任务队列

新版本0.2.0保留原TaskSubmitter回归，增加SQLite持久队列和服务边界。场景来源于固定harness的租约/代际持久化，以及trading账本的发布前写入与请求指纹机制。

验收重点是同键内容冲突、跨进程原子领取、租约过期后的代际隔离、真实子进程在提交前后退出，以及完成状态和结果的事务一致性。恰好一次只在已声明的持久账本范围内成立，不能用它承诺外部副作用不会重放。

### GRAPH-04：增量图与诊断发布

新版本0.2.0保留Invalidator原接口，增加独立的批次图更新、反向索引、待处理集合与诊断快照发布模块。来源是cwtools固定提交的RefreshCoordinator、DiagnosticInvalidation和Program内分离准备/发布机制；不把来源提交中不存在的模块冒称为复制来源。

验收覆盖增删改依赖、循环/菱形图、删除后未解析引用及重建、累计失效集合、准备失败不污染确认快照，以及旧代准备结果晚到不能覆盖新代。通过受信回调的实际调用集合与全量oracle比较，检验增量结果和工作量，不能靠自报计数通过。

两题的题面描述故障症状、公共接口与约束，避免直接给出修复顺序。至少三类相互作用的不变量需要同时成立；文件数或行数不作为达标条件。

## 对测试本身做反例验证

`pnpm task:mutants <ID>` 在参考实现基础上应用作者预声明的近似错误修复。声明保存在 `graders/<ID>/mutants.json`，补丁在同题mutants目录，均不随候选题目包发布。

1. 先确认参考实现全部通过；基线失败即停止。
2. 每个错误修复只修改starter，公开检查及任务说明受保护。
3. 再运行完整公开/隐藏检查，要求预声明的目标检查全部失败；其它已声明检查的交叉不变量失败保留为additionalFailures，不反向改写目标。starter三向验证仍要求完整失败集合精准匹配。
4. 编译/启动错误、超时、缺失检查、额外未声明检查都不能算有效检出。
5. 同时保留未检出、非预期失败和全部原始输出；不在观察结果后自动改写预期。

这能排除“只测到一个刻意坏的starter”的假象，但选定反例集合仍不是对所有错误实现的证明。参考和结构不同的正确替代也必须继续通过，以防检查绑死一种实现。

## 发布难度的证据要求

当前四级仍为设计标签。后续实际测模型时，应固定作答工具、提示、时间/token预算和尝试次数，保存首次作答，统计各级通过率、典型失败类别与公开通过但隐藏失败的情况，并复核裁判一致性。

本轮没有启动真实模型作答、没有消耗真实裁判调用，也没有重启Windows或进行Linux运行。其余偏局部的高难题如ARCH-04、STATE-03、PERF-04继续列为需要强化/校准的候选，不能因为两题升级就宣称整个题库达到极难水平。

## 本轮验收结果

API-04 0.2.0参考与不同结构替代各通过26项检查；GRAPH-04 0.2.0各通过17项。两题三向六阶段均符合预声明，6/6近似错误修复有效检出，受控回归参考均为50/50。平台172项测试及2项端到端通过。完整路径见 [验收记录](trials/2026-09-14-judge-and-task-quality.md)。这些结果证明新增契约及反例验证可运行，没有给出未经测量的“模型解题率”。
